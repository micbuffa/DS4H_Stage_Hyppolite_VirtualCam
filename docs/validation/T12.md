# Validation T12 — Contrats et orchestration des transitions

Date : 13 novembre 2026. Statut : **T12 terminée et validée**. Les effets graphiques restent à implémenter à T13 et aux étapes suivantes.

## Périmètre livré

Le catalogue comprend les douze modes de la spécification. Les réglages sont validés, bornés, copiés et gelés avant exécution. Le plan conserve les sources initiales, la destination, les cibles et le calendrier par écran ; il retire les cibles déjà sur la bonne source et impose des trajets successifs. Les états « Sans signal » sont représentés sans texture fictive dans le domaine.

L'orchestrateur exécute préparation, passage, présentation finale et validation globale. Il refuse une seconde commande, un lancement pendant un drag et un mode sans adaptateur disponible. Il restaure une session après erreur ou annulation et libère une préparation qui aboutit après abandon. Le directeur conserve les routes validées et permet de préparer d'autres sélections sans changer le plan en cours.

Le chemin coupe est réellement branché dans le runtime. Son signal d'annulation traverse le renderer jusqu'au gestionnaire de flux, qui supprime les candidats et réactive les sources suspendues. Il retire les abonnements temporaires lorsque la transaction est réglée. Aucune passe de captation supplémentaire n'est créée au repos.

Les futurs adaptateurs disposent des contrats de session et de possession par consommateur. Le calcul pur distingue sources actives, allocations et consommateurs ; les plafonds 3/4/5 sont explicites. L'horloge reçoit des temps monotones et les événements de visibilité : le concert peut être en pause sans arrêter le passage, et le temps caché n'est pas rattrapé.

## Tests métier et adaptateurs

`npm run check` réussit : TypeScript strict, ESLint, **227 tests unitaires et d'intégration**, puis build. Cela représente 43 tests supplémentaires par rapport au socle : 42 dans `transitionPlanning.test.ts` et `transitionOperation.test.ts`, et un test natif ajouté à `integration/babylon/routing.test.ts`.

Les tests couvrent les modes et paramètres invalides, les durées non finies et bornées, les IDs et cibles invalides, les cibles mixtes, le cas A=B, l'immuabilité du plan, les délais et progressions, la concurrence, les verrous exposés, la visibilité et le refus des modes non disponibles. Les erreurs sont injectées avant le passage, pendant son rendu et pendant la présentation finale. L'annulation est vérifiée après une première étape déjà visible, pendant la préparation et après la bascule des textures d'une coupe.

Les tests d'effets utilisent des ports simulés : leurs images intermédiaires ne constituent pas des rendus GPU validés. Le nouveau test NullEngine vérifie que l'annulation libère réellement une RTT native en préparation et laisse la texture C1 et ses consommateurs intacts ; il ne prouve pas la qualité de l'image.

## Recette navigateur Windows

Environnement : Windows NT 10.0.26200.0, Node.js 26.13.1, npm 11.20.0, Playwright 1.65.0, Chrome installé 157.0.8103.78, BabylonJS 9.34.0. Viewport 1280 × 720. La configuration de test force WebGL2 via ANGLE/SwiftShader ; ces vérifications ne mesurent pas le GPU matériel.

La première tentative en environnement restreint était bloquée par `EACCES` sur l'accès au serveur local. Les tests ont ensuite été exécutés avec l'accès local requis. Le premier lancement parallèle dépassait le délai de navigation ; le parcours isolé a réussi. Une exécution intermédiaire a été interrompue par un rechargement Vite pendant les dernières modifications. Les résultats retenus ci-dessous proviennent du code applicatif figé et d'un seul worker.

Six références Windows ont été produites et inspectées avant comparaison : groupe rapproché, mire asymétrique, C4, C7, C8 et C9. Elles conservent leurs noms `*-win32.png` ; les références macOS sont inchangées. L'inspection vérifie les quatre musiciens et instruments, l'orientation des labels de la mire, le contrechamp avec public et l'absence d'aides dans les cadrages.

Commandes PowerShell :

```powershell
$env:PLAYWRIGHT_CHROMIUM_CHANNEL = 'chrome'
npm run test:e2e -- --grep 'nine distinct|closer view|calibration image' --update-snapshots --workers=1 --timeout=90000
npm run test:e2e -- --workers=1 --timeout=90000
npm run test:e2e -- editing.spec.ts --grep 'drags world axes|moves and turns C4' --workers=1 --timeout=180000
```

La génération des références a réussi ses trois tests ; elle n'est pas utilisée seule comme preuve de non-régression. La suite complète sur code figé a donné **35 réussites, deux dépassements de délai d'édition et un benchmark exclu**, en 12,5 minutes. Les deux parcours d'édition avaient une limite locale de 60 secondes, prioritaire sur le délai de commande. Ils ont été relancés après passage de cette limite à 180 secondes : **deux réussites en 2 minutes**, sans modifier leurs assertions, les données ni le code applicatif. Au total, les **37 parcours fonctionnels sont validés**.

Ces parcours couvrent les dix scénarios du socle, les images en direct, le partage des flux, l'édition sur les trois axes et en rotation, le FOV de C8 partagé, les cinq interruptions de geste, la réalisation pendant pause, le retour régie, les erreurs et les changements de qualité. Les tests de stabilité ont également réussi les **100 coupes** et les **20 cycles de montage/démontage**. La [capture Windows des trois sources](captures/T12-trois-sources-windows.png), inspectée à 1280 × 720, montre C2, C5 et C9 avec les états du pupitre lisibles.

La recette de performance séparée n'a pas été exécutée à T12 et reste à relancer sur matériel réel à T19. Aucune cadence matérielle n'est déduite de ces tests logiciels.

## Limites et suite

Aucun fondu, volet, Rolling Cubes, Mosaïque, Grid Morph ou autre effet n'est encore affiché dans l'application. Le choix d'un mode sans driver est refusé. Les boutons de transition, les matériaux/shaders, les acquisitions par lease, le moniteur et la caméra temporaire appartiennent aux étapes suivantes. Les verrous de caméra et de qualité sont exposés à ces futurs adaptateurs ; le runtime T12 applique déjà le refus du lancement pendant un drag.

La [décision 0006](../decisions/0006-transitions-previsualisation-et-budgets.md) décrit les contrats et la politique prévue pour les couleurs. La compilation et les pixels des shaders seront vérifiés à T13. Le build conserve l'avertissement de taille du chunk principal supérieur à 500 kB ; il n'empêche pas sa production.
