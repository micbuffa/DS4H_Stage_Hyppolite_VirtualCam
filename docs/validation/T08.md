# Validation T08 — Panneau de réalisation 3D

Recette du 10 novembre 2026 sur macOS, avec BabylonJS 9.34.0 et Chromium WebGL2 via SwiftShader.

Le pupitre utilise des volumes BabylonJS pour le caisson et les touches, avec des textures Canvas pour les libellés. Cette construction permet de traiter les appuis, le survol et les relâchements avec le même picking que les autres objets de la scène. Le panneau est légèrement incliné à droite au premier plan, à Z = −12. Ce placement laisse les trois écrans et les neuf labels de caméra visibles à 1280 × 720. Les commandes de réalisation sont sur le pupitre. Le bandeau HTML affiche les états et donne accès à l’aide et au retour à la vue régie.

Les tests unitaires vérifient les états des douze touches numérotées, les commandes d’édition, les cibles vides, les coupes en cours et les erreurs de diffusion. Ils vérifient aussi la consommation d’un clic et l’annulation d’un glissement. L’intégration NullEngine contrôle la hiérarchie, le marquage des maillages et la libération des ressources du panneau.

Les parcours Chromium utilisent les vrais volumes cliquables. Ils vérifient les neuf sélections, le routage sur une ou plusieurs cibles, le FOV, les modes d’édition, l’aide et la stabilité de la vue pendant un glissement sur le panneau. La recette GPU cadre le panneau avec trois sources distinctes. Les pixels de chaque flux diffèrent lorsque le panneau est temporairement rendu filmable dans la scène de test. Cela confirme son exclusion effective avec la configuration de production.

`npm run check` réussit avec 159 tests unitaires et d’intégration. La suite Playwright réussit ses 31 tests avec trois workers.

La capture initiale a été inspectée à 1280 × 720 après correction du sens vertical des textures Canvas. La commande Pause reste visible et désactivée jusqu’à T10. Les mesures de performance et la validation sur matériel de référence restent prévues à T11.
